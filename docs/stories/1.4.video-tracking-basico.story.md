## Story

**Como** equipe do Gestar em Movimento,
**Quero** registrar quando uma gestante clica em Play e quando termina de assistir um vídeo,
**Para que** tenhamos dados reais de engajamento para validar se o conteúdo em vídeo é valioso para o produto.

## Acceptance Criteria

1. Quando a usuária clica no botão Play de um vídeo, um evento `video_play` é registrado na tabela `video_progress` no Supabase.
2. O evento `video_play` contém: `user_id`, `exercise_id`, `youtube_video_id`, `event_type: 'play'`, `occurred_at` (timestamp).
3. Existe migration SQL criando a tabela `video_progress` com os campos necessários e índices adequados.
4. O registro do evento `video_play` é feito de forma não-bloqueante — se falhar, o vídeo continua tocando normalmente (fire-and-forget com erro logado no console).
5. Quando o YouTube iframe emite o evento `onStateChange` com `YT.PlayerState.ENDED` (state = 0), um evento `video_completed` é registrado na tabela `video_progress`.
6. O AC5 é best-effort via YouTube IFrame API: se o evento não for capturado (ex: usuária fecha a aba), não é problema para o MVP.
7. A função de tracking NÃO está acoplada ao componente `YouTubePlayer.tsx` — é uma função utilitária chamada de fora (via prop callback ou hook dedicado).
8. TypeScript não gera erros (`npm run typecheck` passa).
9. Lint passa sem novos warnings (`npm run lint`).

### Schema da tabela `video_progress`

```sql
-- supabase/migrations/2026-05-25_create_video_progress.sql
CREATE TABLE IF NOT EXISTS video_progress (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  exercise_id   TEXT NOT NULL,
  youtube_video_id TEXT NOT NULL,
  event_type    TEXT NOT NULL CHECK (event_type IN ('play', 'completed')),
  occurred_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_video_progress_user_exercise
  ON video_progress(user_id, exercise_id, occurred_at DESC);

CREATE INDEX IF NOT EXISTS idx_video_progress_user_event
  ON video_progress(user_id, event_type, occurred_at DESC);

-- RLS
ALTER TABLE video_progress ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Usuária vê próprios eventos de vídeo"
  ON video_progress FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Usuária insere próprios eventos de vídeo"
  ON video_progress FOR INSERT
  WITH CHECK (auth.uid() = user_id);

COMMENT ON TABLE video_progress IS 'Evento log de visualizações de vídeo — MVP analytics para validar engajamento com conteúdo em vídeo';
COMMENT ON COLUMN video_progress.event_type IS 'play = usuária iniciou o vídeo; completed = vídeo chegou ao fim';
```

**Atenção RLS:** O projeto usa autenticação customizada (`lib/customAuth.ts`). Verificar se `auth.uid()` funciona com o sistema atual ou se a política RLS precisa ser adaptada para usar a coluna `user_id` via join com `users`. Padrão atual visto em `supabase/migrations/2026-05-24_event_log_architecture.sql` deve ser seguido.

### Padrão de tracking (fire-and-forget)

```typescript
// lib/tracking/videoTracking.ts
import { supabase } from '@/lib/supabase'

export interface VideoTrackEvent {
  userId: string
  exerciseId: string
  youtubeVideoId: string
  eventType: 'play' | 'completed'
}

export async function trackVideoEvent(params: VideoTrackEvent): Promise<void> {
  const { error } = await supabase.from('video_progress').insert({
    user_id: params.userId,
    exercise_id: params.exerciseId,
    youtube_video_id: params.youtubeVideoId,
    event_type: params.eventType,
  })
  if (error) {
    console.error('[VideoTracking] Falha ao registrar evento:', error.message)
    // Não relança — fire-and-forget, vídeo continua tocando
  }
}
```

### YouTube IFrame API — Complexidade

Capturar o evento `ENDED` exige usar a YouTube IFrame API (JS SDK), não apenas um `<iframe>` simples. Isso adiciona complexidade ao componente.

**Simplificação recomendada para MVP:** Se a integração da IFrame API for complexa demais na Story 1.3, o evento `completed` pode ser implementado como um timer simples:
- Registrar `completed` após `(duration * 60 * 0.9)` segundos de vídeo tocando (90% da duração)
- Isso é uma aproximação aceitável para analytics de MVP

**Decisão:** o @dev escolhe a abordagem mais simples que atenda ao AC5. Documentar a escolha nos Dev Agent Records da story.

### Integração com customAuth
