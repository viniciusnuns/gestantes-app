## Story

**Como** desenvolvedor do Gestar em Movimento,
**Quero** adicionar a coluna `youtube_video_id` na tabela de exercícios e popular 5 exercícios com IDs reais de vídeos unlisted do YouTube,
**Para que** o sistema tenha os dados prontos para a integração de vídeo sem precisar alterar a estrutura de dados no futuro.

## Acceptance Criteria

1. A migration SQL cria a coluna `youtube_video_id TEXT` (nullable) na tabela `exercises` (ou no equivalente em `lib/data.ts` se a tabela ainda não existir no Supabase).
2. A interface `Exercise` em `lib/data.ts` inclui o campo `youtube_video_id?: string`.
3. Pelo menos 5 exercícios do array `exercises` em `lib/data.ts` possuem `youtube_video_id` preenchido com IDs válidos de vídeos YouTube unlisted (formato: string de 11 caracteres, ex: `"dQw4w9WgXcQ"`).
4. O campo `youtube_video_id` é opcional (nullable) — exercícios sem vídeo continuam funcionando normalmente.
5. Nenhuma quebra de funcionalidade existente: a página `/biblioteca/[id]` carrega sem erros para exercícios com e sem `youtube_video_id`.
6. TypeScript não gera erros (`npm run typecheck` passa).
7. Lint passa sem novos warnings (`npm run lint`).

### Contexto Arquitetural

**DECISAO ATUAL DO PRODUTO:** O MVP usa YouTube unlisted (validação barata). A decisão anterior de Aria (@architect, 2026-05-25) recomendou Mux + HLS nativo — essa recomendação foi SUBSTITUIDA pela decisão do product owner de usar YouTube como primeiro passo de validação. A migração para Mux/Bunny.net ocorrerá após validação de engajamento.

**Estrutura atual dos dados:**
- Exercícios estão como mock estático em `lib/data.ts` (array `exercises`, interface `Exercise`)
- NÃO há tabela `exercises` no Supabase ainda — os dados são carregados do arquivo TypeScript
- A migration SQL deve ser criada de forma preventiva para quando a tabela for criada no Supabase
- `app/biblioteca/[id]/page.tsx` busca: `exercises.find((ex) => ex.id === params.id)` — fonte é `lib/data.ts`

**Estrutura do Exercise desejada após esta story:**
